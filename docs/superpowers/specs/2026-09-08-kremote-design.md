# kremote — Design

Remote access tool for personal use: control this Windows machine's terminal
and files from a browser anywhere. Modeled on 9Remote (docs.9remote.cc) but
simplified — no relay SaaS, single owner.

**Decided in brainstorming:**
- Purpose: personal tool (not a public product)
- MVP: Terminal + File Explorer with Git integration. Remote Desktop is out of scope.
- Relay: a Node process on a cheap VPS (option B). Agent dials out; no cloudflared needed on Windows.

## 1. Architecture

```
[Agent: Windows]  ──WSS dial-out──▶  [Relay: VPS]  ◀──WSS──  [Browser]
   node-pty, fs, git                   pairing + web UI        xterm.js, CodeMirror
```

- Agent runs on the Windows machine, opens an outbound WebSocket to the relay,
  and stays connected. No public IP, no port forwarding on the Windows side.
- Browser connects to the relay; relay pairs browser ↔ agent and pumps bytes
  both ways. Relay never parses terminal content.
- TLS terminates at Caddy on the VPS (automatic HTTPS) reverse-proxying to the
  Node relay on 127.0.0.1:8787.
- Monorepo, npm workspaces, 3 packages:
  - `packages/agent` — CLI daemon on Windows
  - `packages/relay` — server + built web UI (`packages/relay/web` is a Vite app, built into `relay/public`)
  - `packages/shared` — `protocol.ts` types only

## 2. Protocol

One WebSocket per paired agent↔client. JSON frames, `{type, id?, ...payload}`;
requests carry `id`, responses echo it.

- Lifecycle: `term.open`, `term.close`, `term.list`
- Terminal stream: `term.data` (agent→client), `term.input` (client→agent), `term.resize`
- Files: `fs.list`, `fs.read`, `fs.write`, `fs.mkdir`, `fs.rename`, `fs.delete`
- Git: `git.status`, `git.diff`, `git.commit`, `git.push`, `git.log`

`term.data` ships as raw strings inside JSON. Escaping overhead is acceptable
for a personal tool.

```
// ponytail: JSON instead of binary framing. Upgrade path: if the terminal
// feels laggy over 4G, send term.data as WS binary frames; protocol unchanged.
```

## 3. Auth

- **Agent**: `DEVICE_KEY` generated by `relay keygen`, stored hashed on the
  relay (JSON file on the VPS is enough). Agent keeps the plaintext key in
  `~/.kremote/config.json`. One key per device.
- **Browser**: `ACCESS_KEY` — short-lived one-time key the agent prints at
  startup (and as a QR code). Browser opens the relay URL, enters key, relay
  issues a session token. Idle sessions disconnect.

Trust boundary — not simplifiable: every `fs.*` / `git.*` path argument is
resolved against a configured root and rejected if it escapes the root
(path-traversal guard, covered by tests).

## 4. Limits (guardrails, not features)

- 100 KB max per `fs.write` request
- 10 MB max `fs.read` (text files only; binary rejected)
- Sessions: max 4 concurrent browser sessions per device

## 5. Terminal on Windows

`node-pty` (ConPTY under the hood; Windows 10 19045 is supported).

**Known risk:** node-pty is a native module; prebuilt binaries may be missing
for Node v24. Mitigation order:
1. Try `npm install` with prebuilds (first spike, before any other code)
2. If missing: install VS Build Tools and compile
3. Fallback: pin the project to Node v22 LTS

## 6. Web UI

- Terminal: `xterm.js` + fit + web-links addons, multi-tab sessions
- Editor: CodeMirror 6 (Monaco rejected — 10x heavier for the same result)
- File tree: hand-rolled, lazy-loads one directory at a time
- Git panel: status list + unified diff view, commit message box, push button
- Mobile: on-screen Ctrl/Alt/Shift/Esc/Tab/arrow keys, like 9Remote
- No framework beyond Vite + vanilla TS/HTML for the UI (small enough)

## 7. Testing

`node:test` (builtin, no framework). One test file per non-trivial module:

- path-traversal guard (must reject `../`, symlink escape, absolute paths outside root)
- `fs.write` mtime-conflict check (reject save if file changed since read)
- relay pairing: connect, match, agent-offline transition
- protocol encode/decode round-trip

## 8. Build order

1. **Spike: node-pty on Node 24** — decides the stack, do it first
2. Relay WS pairing + multi-session terminal + web terminal → usable end-to-end
3. File explorer + editor
4. Git panel

## 9. Explicitly out of scope (YAGNI)

- Remote desktop / screen streaming (phase 2 candidate, WebRTC or tile-based)
- Multi-user, accounts, billing
- File upload/download of binary files
- Audio
